# 独立 held-out 语料 · 第二轮（V-F08，§16.4）

## 它是谁写的

四位**新的**撰写人，与第一轮不是同一批，同样没有读过词表、用途表、引擎，也没有读过仓库里
任何一份语料（包括第一轮那份）。

| 文件 | 撰写人设定 | 命令数 |
|---|---|---:|
| `writer-e-dba.toml` | 接手了一个 Redis 集群的 DBA，关心 key、内存、过期、生产上能不能跑 | 48 |
| `writer-f-game-backend.toml` | 游戏后端，按玩家 / 房间 / 背包 / 段位 / 排名描述 | 65 |
| `writer-g-payments.toml` | 支付公司的工程师，按保证描述（幂等、只写一次、不重复扣款） | 50 |
| `writer-h-beginner.toml` | 边做小项目边学 Redis 的人，不熟术语，说法朴素甚至笨拙（**刻意保留**） | 36 |
| | **合计** | **196 条命令 / 398 句** |

hyperloglog 的三条命令被分给了两位撰写人，所以它们各有 4 句而不是 2 句；多出来的是两种语域的
独立表述，留着比删掉有用。

## 首次接触的数字（词表已封存，只测这一次）

| 指标 | §16.4 门槛 | 第一轮首测 | **第二轮首测** |
|---|---:|---:|---:|
| top-3 | ≥ 80% | 67.3% | **69.6%**（277 / 398） |
| top-5 | ≥ 90% | 75.5% | **76.6%**（305 / 398） |

## 这个数字说了一件比「没过」更重要的事

两轮之间做了一次完整的扩表：**+164 个词条、+6 条 implication、修正了 3 个指错族的概念标注、
给 8 个命令补了概念**。在第一轮那份语料上，这次扩表把 top-3 从 67.3% 抬到了 86.5%。

而在一份**新的**独立语料上，它只从 67.3% 变成 69.6%。

**+19.2 个百分点里，只有 2.3 个百分点是泛化，其余 16.9 个是记住了第一轮那份语料的具体措辞。**
这不是推断，这是两个数字相减。

第一轮的 ADR-034 把不收敛归因于「四份语料同一个作者」。那个解释现在被排除了：这两轮的撰写人
互不相同，也都没看过词表。**剩下的解释是机制本身**——一张手写的同义词表覆盖的是写表人想到的
说法，而语言不是这样分布的。再写第五份、第六份语料，只会把这条曲线继续画成同一个形状。

结论写进 [ADR-034](../../../docs/adr/ADR-034.md) 的更新里：要过 §16.4 的 80/90，
需要换匹配机制，而不是继续加词。门槛一个字没有改。
