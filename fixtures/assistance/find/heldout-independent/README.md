# 独立 held-out 语料 · 第一轮（V-F08，§16.4）

## 它是谁写的

四位撰写人，**都没有看过词表、用途表、引擎，也没有看过本仓库里任何一份已有语料**。
每人拿到的只有：一份命令名清单、一个语气设定、以及「写你会在搜索框里打什么」。

| 文件 | 撰写人设定 | 命令数 |
|---|---|---:|
| `writer-a-backend-engineer.toml` | 每天用 Redis 的后端工程师 | 40 |
| `writer-b-sre.toml` | 救火与赶工中的 SRE，说法偏运维 | 41 |
| `writer-c-app-developer.toml` | 刚接触 Redis 的应用开发，按产品功能描述（队列、排行榜、群发） | 53 |
| `writer-d-data-engineer.toml` | 数据工程师，按数据形状与操作描述，偏精确简短 | 62 |
| | **合计** | **196 条命令 / 392 句** |

四种语域是刻意的。ADR-034 记录的失败模式是「四个语料都是同一个作者写的，于是每个 held-out 集
其实是『我还没想到要覆盖的那个语域』」。四个不同设定的撰写人，一次就给出了四个语域。

## 为什么这次的独立性是真的

上一轮的三个语料（`../heldout-v1-void/`、`v2`、`v3`）与 canonical 集出自同一只手，所以
「没见过」只是「还没想到」。这一轮的撰写人**在物理上没有读过**词表：他们被明确要求不打开仓库里
任何文件，产出也只有一个文件。392 句里与既有语料**逐字相同的只有 2 句**——`GETBIT` 的
"read a single bit at an offset" 与 `GETDEL` 的「取出值的同时把 key 删掉」。那不是抄，
那是两个人写出了同一句显而易见的话；两句都请原作者改写成了别的说法，改写时同样没有看词表。
（这一步只泄露了「这句话已经存在」这一个比特，对 2/392 句，且留在这里可审计。）

**残余的不独立性，写在这里而不是不提**：撰写人与实现者都是语言模型，共享预训练分布，所以
「独立」的强度弱于一位从未接触过这个项目的人类。它比同一作者写四遍强得多，但不等于人类语料。
真正的人类语料到达时，按同样的流程再测一次即可——这份记录会成为对照。

## 首次接触的数字（**改词表之前**测的，只测这一次）

| 指标 | §16.4 门槛 | 实测 |
|---|---:|---:|

同一时刻的对照：canonical **97.8%**，三个作废语料合计 77.6%。

**未达标。** 30 个百分点的差距不是调参能补的，它说明词表覆盖的是我们想到的说法。
miss 的形状很清楚，分两类：

1. **词不在表里**：「把这几个 key 干掉」（口语的「干掉」）、"serialize a value so it can be
   rebuilt later"（序列化 / 还原）、"have a key die at a given unix time"（绝对时间戳）、
   "make a key permanent again"（去掉过期）、「这个 key 多久没人读过了」（空闲时间）。
2. **词在表里但排序错**："set a timeout in seconds on a key" 把 `EXPIRE` 排在第 5，
   前面全是 `SETEX` / `HSETEX` / `PSETEX` / `HEXPIRE`——`key` 与 `field` 的族区分在排序里
   没有起作用。
