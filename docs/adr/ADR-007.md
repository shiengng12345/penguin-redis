# ADR-007 · `UnknownAfterSend` 是正式 outcome；写命令不盲目重试

- **状态**：accepted
- **日期**：2026-09-16
- **依据**：v2.1 §22.1、§22.2、§22.5、STATE-01、NET-06
- **Phase 0 验证项**：V-B04、V-B05、V-G02

## Context

命令字节可能已到达服务器而回复丢失；「没收到回复」≠「没执行」。按命令名建白名单重试过于粗糙（TTL、条件参数、并发都会改变语义）。

## Decision

请求状态机 Prepared→Approved→Sending→AwaitingResponse→Confirmed，任一断点进入 `UnknownAfterSend`/`CancelledBeforeSend` 等一等 outcome，退出码 6。默认不自动重放任何写命令；重连后不重建事务、不重订阅（可选重订阅必须标 gap）。

## Consequences

需要四维度结果模型（ADR-021）；差异测试用两套独立实例；Sentinel failover 后写标 unknown。

## 结果 / 验证记录

**PASS**（2026-09-16，V-B04、V-B05、V-G02）。

`crates/pr-protocol/tests/outcome_matrix.rs` 12 个测试把状态机的每个断点映射到 outcome，`UnknownAfterSend` 退出码 6。`crates/pr-core/src/session.rs` 18 个测试证明重连后不重建事务、不自动重订阅，可选重订阅必须标 gap。V-G02 的 Sentinel failover 是这条规则的真实检验：强制切主之后，飞行中的写**不被重放**——它可能已经在旧主上生效了，重放一次就是执行两次。
