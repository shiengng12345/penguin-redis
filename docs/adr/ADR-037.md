# ADR-037 · 终端与我们对字符宽度的分歧由「每格重置光标」降级绘制承担；`CSI 6 n` 探测只在 TTY 且由用户触发

- **状态**：accepted
- **日期**：2026-09-16
- **依据**：v2.1 §14.6、R33、UX-08、ASSIST-018/067
- **Phase 0 验证项**：V-C04、V-J04

## Context

ambiguous width、ZWJ 序列、组合字符在不同终端里的实际占位不一致，而表格绘制依赖「这个字符占几列」这个数。计划对本项写的是**无回退**——策略已经是可实现契约，不允许降级成「宽度算不准就不画框」。

## Decision

**固定宽度策略 + 降级绘制**，两者都是契约的一部分：

- 默认按固定策略计算显示列数。
- `DrawMode::CursorReset`：在每个单元格边界发送**绝对**光标移动，而不是依赖「我们写了 N 个字符所以光标在第 N 列」。这样即便终端对某个字符的宽度判断与我们不同，框线仍然对齐——错位被限制在单元格内部，不会累积到整行。

**`CSI 6 n` 探测是可用的，但被三条限制框住**：仅 TTY；仅用户显式触发（`prc --probe-width`），不在启动路径上；非 TTY 直接拒绝且**一个字节都不写**。无应答 500 ms 放弃而不是挂起。发现一处分歧即切换到 `CursorReset`。

## Consequences

- 降级绘制**不能靠「渲染完再读回自己的输出」来证明**——那只说明渲染器同意自己。测试必须用一种宽度模型渲染、用另一种模型显示。
- 探测是一次会写进终端输入流的往返；把它放在启动路径上意味着每次启动都在向一个可能不回答的对端提问。用户触发是这个能力可以存在的条件。

## 结果 / 验证记录

**PASS**（2026-09-16，V-C04）。

降级绘制的测试按上面那条要求写：屏幕模型的 `CellWidth::UnicodeWide` 扮演 CJK 终端，用 narrow 策略渲染的 padded 表格右边框**逐行漂移**——测试先断言这个漂移真的发生（否则降级测试是空的），再断言 `CursorReset` 下框线仍然对齐。

过程中修正了屏幕模型的两个真实错误（组合字符与 ZWJ 的归属），它们此前让仿真终端比真实终端更宽容。

`CSI 6 n`：非 TTY 路径有「零字节写入」的断言；无应答走 500 ms 超时而非挂起；一处分歧即切换。

人工记录 `MV-V-C04-*`（真实终端的实测宽度）编号已分配，未执行；不阻塞——UX-08 在仿真下已过，且降级绘制的正确性**不依赖**宽度判断正确，这正是它存在的理由。
