# ADR-014 · 完整测试与发布证据属于每个阶段，不是最后补

- **状态**：accepted
- **日期**：2026-09-16
- **依据**：v2.1 §32、§34、§36.2、phase-plan G5
- **Phase 0 验证项**：V-A01、V-A02、V-A03、V-A04、V-A05

## Context

「先没有测试以后补」把基础正确性变成技术债；截图漂亮不等于正确。

## Decision

每个功能的完成定义包含失败流程测试；每个 Phase 有出口门禁；Phase 0 先建 harness（PTY、differential、synthetic RESP、fault injection）与 CI 矩阵；无法自动化的有人工记录模板并同为发布门禁；bug 修复先加复现 fixture。

## Consequences

CI 门禁表 §34.2；release evidence bundle §34.3；flaky 必须定位不许重跑到绿。

## 结果 / 验证记录

**PASS**（2026-09-16，V-A01~V-A05）。

四个 harness 全部在 Phase 0 先建成并进 CI：PTY（`xtask/pty-harness`）、differential（`xtask/differential` + `ci/check-differential.sh`）、synthetic RESP server（`xtask/resp-server` + 316 样本）、fault injection（`xtask/src/fault.rs`）。CI 矩阵三平台绿（run 35053565259）。无法自动化的部分有编号的人工记录（`docs/manual-verification/`，MV-V-C03/C04/C05），模板本身是 P0-META-03。本条 ADR 在 Phase 0 内被反复兑现：SPIKE-003 的三个 ConPTY 缺陷、`TaskScope` 的句柄泄漏、`~?` 被解成 Array——每一个都是**先加复现用例再修**，这也是它们能被写进报告的原因。
