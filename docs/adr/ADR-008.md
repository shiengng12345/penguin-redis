# ADR-008 · CLI / TUI / MCP / recipe / `--pipe` 全部经过同一 execution kernel 与 policy

- **状态**：accepted
- **日期**：2026-09-16
- **依据**：v2.1 §19.1、§17.4、§18.5、§29.4、ASSIST-080
- **Phase 0 验证项**：V-B03、V-D08、V-C02

## Context

多入口各自连 Redis 会形成多套暗中不同的语义，也让策略可被绕过。

## Decision

所有请求构造为 `CommandRequest` 经 `pr-application` → policy/budget/approval → `pr-core` kernel。TUI 不自带连接逻辑；`--pipe` 逐帧解析后走同一路径（ADR-025）；MCP 工具面是受限包装。

## Consequences

任何新入口都需要 transport-spy 测试证明经过 kernel；差异测试覆盖入口而非仅命令。

## 结果 / 验证记录

**PASS**（2026-09-16，V-B03、V-D08、V-C02）。

三个入口分别走到同一条路上并各自留证：`--pipe` 在 `crates/pr-application/src/pipe.rs`（14 tests）逐帧解析后构造 `CommandRequest`；MCP 在 `crates/pr-mcp/`（9 + 17 + 3 tests）把工具面收窄成一层包装，而不是另一套执行逻辑；TUI 在 `crates/pr-terminal/`（19 + 7 PTY tests）不持有任何连接。V-D08 里 `prc --mcp-stdio` 的分叉点**在参数契约之前**——这是有意的：MCP 通道不继承 CLI 的默认值，否则两个入口会有两套默认。
