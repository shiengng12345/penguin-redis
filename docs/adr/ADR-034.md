# ADR-034 · 用途搜索的 held-out 指标需要一位**不是实现者**的撰写人；该输入是 Phase 0 出口依赖

- **状态**：accepted
- **日期**：2026-09-16
- **依据**：v2.1 §16.4、R10、ASSIST-050/051
- **Phase 0 验证项**：V-F08、V-J04

## Context

§16.4 给用途搜索两条指标，而不是一条：

| 集合 | 门槛 | 证明了什么 |
|---|---|---|
| canonical | top-3 ≥ 95% | 词表**完整**——仅此而已，因为词表就是用它构建的 |
| held-out | top-3 ≥ 80%、top-5 ≥ 90% | 它能**推广**到没有参与构建的表述 |

并对 held-out 集写明：「由**不参与词表构建的人**独立撰写」。回退条款是：「未达标 → 扩词表后 held-out 集换新（旧集作废，防止泄漏）」。

## 实测：三轮，三个语域，首次接触时的数字

| 集合 | 语域 | 首测 top-3 | 之后 |
|---|---|---:|---|
| v1 | 口语 + 业务名词（「做个分布式锁」「队列积压了多少」） | **22.7%** | 扩词表 → 作废 |
| v2 | 搜索框式短查询（「左出阻塞」「bulk read」） | **74.7%** | 扩词表 → 作废 |
| v3 | 任务式间接表述（「一条记录里只改其中一项」） | **42.9%** | 扩词表 → 作废 |

canonical 在三轮中始终 ≥ 95%（现 97.8%）。

数字不收敛，原因在数字里就看得见：**四个语料（canonical 与三个 held-out）都是同一个作者写的**。于是每个「held-out 集」实际上是「我还没想到要覆盖的那个语域」，而不是一次独立抽样。v2 比 v1 高，是因为 v1 的扩词表恰好覆盖了 v2 用的词；v3 又掉下来，是因为它换了第四种说法。

**再写第四个语料不能解决这件事。** 靠足够多轮达成的「通过」，只说明我最终写出了一个我自己的词表应付得了的语料——而这正是 §16.4 的独立性要求要防的那件事。

## Decision

**门槛一个字都不改。** 80% / 90% 仍然是门槛。改的是它由什么输入来判定，以及在输入到位之前系统处于什么状态。

1. **canonical 门槛立即生效**，CI 强制（`canonical_recall_meets_the_gate`，现 97.8% ≥ 95%）。
2. **held-out 门槛以「自动生效」的形式等待输入**：`heldout_recall_meets_the_independent_gate` 在 `fixtures/assistance/find/heldout-independent/` 不存在时打印一行说明并跳过；该目录一旦出现，它立刻开始强制 80%/90%。没有开关要记得打开，没有测试要记得重新启用——唯一需要发生的事，正是一个 agent 无法替自己完成的那件事。
3. **防止拿旧语料充数**：`the_independent_corpus_would_not_be_one_of_the_corpora_that_built_the_vocabulary` 逐条比对，独立语料不得复用任何构建过词表的句子。
4. **词表封存**：`the_vocabulary_is_sealed_against_the_corpora_that_built_it` 记录词表的 blake3。任何改动都会让它红，提示必须单独提交并在前后各测一次。独立语料到达时，**必须先测再扩词表**——那一次测量是 §16.4 的门槛唯一可以读数的时刻。
5. **三个作废语料全部留在仓库里**（`heldout-v{1,2,3}-void/`），不删。删掉它们会让词表看起来一直就认识那些词，扩表过程也就无法审计。

## Consequences

- **V-F08 记为 BLOCKED，不是 PASS，也不是 FALLBACK-ADOPTED。** 回退条款要求的动作（扩词表 + 换新集）已经做了两轮；剩下的缺口不是工程量不够，而是缺一个我无法提供的输入。把它记成 FALLBACK-ADOPTED 会让 Phase 0 的出口门禁在一条数值指标未达成的情况下通过，那是降低标准。
- **解除阻塞的条件是具体、可执行的**：一个不参与词表构建的人，为 `fixtures/assistance/find/README.md` 中列出的 196 条命令，每条写 2 条自己的表述（中英不限），放进 `heldout-independent/`。约 392 句。写完**不要看测试结果再改**——看了就不再是 held-out 了。
- 这条与 V-I03 的「人工法务确认」、V-C03/C04/C05 的「人工终端记录」同一形状：blueprint 已经承认有些验收需要人的输入，并且把它们写成发布门禁项而不是假装自动完成。
- 词表本身并没有白做：970 条词、114 个概念、196 条命令的用途表，在三个语域上从 22.7% 提升到 77.6%（作废语料合并计算，仅作回归护栏）。这些改进对真实用户有效，与指标是否可判定无关。

## 结果 / 验证记录

**BLOCKED**（2026-09-16，V-F08）。等待 `fixtures/assistance/find/heldout-independent/`。

证据：`crates/pr-intelligence/src/{find,vocabulary}.rs`、`crates/pr-intelligence/tests/find_recall.rs`（13 tests）、`fixtures/assistance/find/{canonical,heldout-v1-void,heldout-v2-void,heldout-v3-void}/`、`fixtures/assistance/find/README.md`。
