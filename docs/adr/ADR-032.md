# ADR-032 · TLS 用 rustls + 显式 CA 集合；不存在关闭校验的开关

- **状态**：accepted
- **日期**：2026-09-16
- **依据**：v2.1 §21.1、§21.3、NET-01
- **Phase 0 验证项**：V-G04、V-J04

## Context

§21.1 要求验证证书与名称、可配置 CA、client certificate、独立 SNI。NET-01 的通过标准补上了决定形态的那一句：**「拒绝或显式配置；无静默 insecure」**。

§21.3 进一步把三件事分开：TCP 目标、TLS 验证名、凭证适用范围。并明确「不能为了可达就关闭 TLS 校验」。

## Decision

**栈选 rustls 0.23，crypto provider 用 `ring`。** 理由是前者默认就没有「接受任何证书」的模式——要绕过校验必须显式实现一个 `ServerCertVerifier` 并调用 `dangerous()`，这是一段任何 review 都看得见的代码，而不是一个 `bool`。`ring` 而非默认的 `aws-lc-rs`，是为了三个 CI runner 上都不需要 C 工具链。

**CA 集合永远来自调用方。** `TlsConfig::new(ca_pem, server_name)` 没有「回退到系统根」的分支，空 bundle 或读不出来都是错误。企业环境要用系统信任库时另开一条显式路径（§21.1 的 Corporate network 一行），且必须同样产出可绑定的 `ca_set_hash`。

**验证名是独立字段**，不从连接的 host 推断。

**放松类 flag 一律拒绝，且拒绝必须给出去处。** `--insecure` / `--no-verify` / `--tls-verify=<非 full>` 在有没有 profile 时都被拒；有 profile 时给更具体的消息。`--tls-ca` / `--tls-name` / `--tls-cert` / `--tls-key` 是那个去处，`--help` 列全，错误信息点名。

## Consequences

- 私有 CA 是**配置出来的**，不是绕过去的。代价是第一次连私有 CA 的服务器需要一个 `--tls-ca`；收益是这一步留下了 `ca_set_hash`，凭证因此绑定到「谁为这台服务器背书」。
- 错误必须说出是哪一项检查失败（名字 / 有效期 / 签发者）。只说「handshake failed」的客户端，是把操作者推向 `--insecure` 的客户端。
- 没有 insecure 模式意味着我们不能用「先连上再说」来调试。换来的是不会有人在生产 profile 上留下一个忘了摘掉的开关。
- rustls 不支持某些老服务器的弱套件。这是刻意的；真要支持时按 §20.4 记录具体版本与具体配置，不是加一个全局开关。

## 结果 / 验证记录

**PASS**（2026-09-16，V-G04 / NET-01）。

矩阵 11 项全绿：正确证书连上并跑通数据；错名 / 过期 / 未知 CA 三项均被拒且错误分别指向名字、有效期、签发者；client cert 要求满足时连上、不满足时被拒；连 `127.0.0.1` 验 `redis.internal` 通过而同证书改用地址当验证名被拒（SNI 独立的两面）；空 / 非 PEM 的 CA bundle 报错而不回退。

命令行侧 6 项全绿，并修掉了一个**真实缺口**：`--insecure` 之前只在有 profile 时被拒，`prc -h host --insecure` 被记录后静默忽略——正是 §21.1 禁止的静默 insecure，且是更坏的一种，因为操作者以为 flag 生效了。

「没有那个开关」由一个源码级测试守住：剥掉注释与字符串字面量后，`dangerous`、`ServerCertVerifier`、`accept_invalid` 等标识符不得出现在 TLS 模块的代码里。先剥字符串是必要的——否则「这里没有 insecure 模式」这句说明本身会触发检查，而人们修这种失败的方式是把说明删掉。

证据：`crates/pr-transport/src/tls.rs`、`crates/pr-transport/tests/tls_matrix.rs`（11 tests）、`crates/prc/src/args.rs`（6 tests）、`tests/topology/tls/README.md`。
