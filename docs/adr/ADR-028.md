# ADR-028 · `pr-json` 是服务器业务 JSON 的唯一权威模型；重复成员以 occurrence 索引寻址；`serde_json` 只用于 Penguin 自有 schema

- **状态**：accepted
- **日期**：2026-09-16
- **依据**：v2.1 §8.3、§8.5、§31.3、R06
- **Phase 0 验证项**：V-E01

## Context

§8.3 的无损规则（重复成员、数字词法、原顺序）不可能用 `serde_json::Value`/`Map` 满足；`RawValue` 只保原文片段无编辑语义（三方评审一致）。

## Decision

`JsonNode { span, kind, Number.lexeme, String.raw, Object.members: Vec<(key, node, occurrence)> }`；路径 `$.a#2`；存在重复成员时无 `#n` 的路径拒绝解析（`ambiguous member`）；编辑只重写目标 span；pretty 是视图操作不回写；`--json` 投影对重复成员的行为在 §18.3 表定义。

## Consequences

新增 crate `pr-json`（V-E01 / SPIKE-004）；Tree/editor/diff/Undo 只接受 occurrence 路径；JSON-05。

## 结果 / 验证记录

**PASS**（2026-09-16，V-E01 / SPIKE-004）。

SPIKE-004 先证明了两个现成选项都不行：`serde_json::Value` 的 `Map` 让后一个重复成员覆盖前一个（**丢数据**），`Number` 归一化词法（`1.2300` → `1.23`，大整数落进 `f64`）；`RawValue` 保留原文但没有可寻址的树，也不支持局部编辑。

采用的模型是 `JsonNode { span, kind }` + 原始缓冲区：标量不存值只存 span，`number_lexeme()` / `string_value()` 按需切片。路径 `$.a#2` 选第 2 个同名成员，**存在重复成员而路径没有 `#n` 时拒绝解析**（`AmbiguousMember`）而不是静默取第一个——静默取第一个正是一个编辑器覆盖错成员的方式。`replace()` 只重写目标 span，含空白与键顺序在内的其余字节逐字节保留。

lone surrogate（`{"s":"\ud800"}`）语法合法但不表示任何 Unicode scalar：**保留文档、拒绝解码**（`string_value()` 返回 `None`），而不是拒绝整个文档。Redis 可以存这种数据，客户端不应因此丢掉它——这是 ADR-005「原始 bytes 权威、解码是视图」在 JSON 层的同一句话。

证据：`docs/spikes/SPIKE-004.md`、`crates/pr-json/`（17 tests，含 DATA-02/03/04、JSON-05、深度预算、`70` / `true` / `null` / 不完整 JSON 均不算 JSON 的自动识别边界、source 字节往返）。16 MiB 单值的时间与内存基准依赖 V-A06 的测量工具，随 Track H 补测，不属于本 spike 的通过条件。
