# ADR-027 · 普通编辑器与 shell argv 是 UTF-8 文本；二进制 / NUL / 无效 UTF-8 只经 §3.2 定义的入口

- **状态**：accepted
- **日期**：2026-09-16
- **依据**：v2.1 §3.2、§11.7、R04
- **Phase 0 验证项**：V-F03、V-B02

## Context

Reedline（及任何 Rust `String` 编辑器）是 UTF-8 边界，装不下无效 UTF-8；OS argv 不能传 NUL。「任意二进制参数」与「普通编辑器精确往返」不能同时成立。

## Decision

六条入口：双引号转义 `"\xHH"` 等（与 redis-cli 一致，fixture 校验）、`-x`、`-X <tag>`、`:send --arg-file`、`:send --arg-hex/--arg-base64`、Guide 二进制槽位。转义只在提交时由权威 tokenizer 解码；显示层永远展示转义形式；含无效 UTF-8 的观察名以转义形式插入并标 `binary name`。

## Consequences

quoting corpus vs `sdssplitargs`（V-F03）；ASSIST-019/083；DATA-01。

## 结果 / 验证记录

**PASS**（2026-09-16，V-F03、V-B02）。

六条二进制入口在 `crates/pr-repl/`（26 tests）逐条实现并测试，双引号转义的解码结果与 `redis-cli` 用 fixture 对照。转义**只在提交时**由权威 tokenizer 解码，显示层永远展示转义形式——一个在屏幕上已经变回原始字节的字符串，无法再被复制粘贴成同一条命令。含无效 UTF-8 的观察名以转义形式插入并标 `binary name`。V-C07 在 Windows 上补上了这条 ADR 的另一半：stdout 是控制台时 Rust 走 `WriteConsoleW`，非法 UTF-8 写不出去，失败是对的，但错误信息必须说出「重定向一下就好」。
