# ADR-004 · Table-first：每 field 横线、强化表头（双线）、JSON 在 value 单元格内多行

- **状态**：accepted
- **日期**：2026-09-16
- **依据**：v2.1 §5.2、§6、REQ-06/07/08、UX-03/04/05
- **Phase 0 验证项**：V-E02、V-C06

## Context

HGETALL 难读、JSON 被挤成一行是用户的第一痛点，且视觉规格已被用户确认。

## Decision

默认 TTY 输出为完整表格：外框、`╞═╪═╡` 表头底线、每逻辑 field 之间 `├─┼─┤`、JSON 在 cell 内 2 空格缩进并语法着色、多行 JSON 不产生额外分隔线。宽度按显示列数、有限采样、流式冻结。

## Consequences

需要自研 TableModel + streaming renderer（V-E02）；不能用通用表格库；无色终端必须保留层级。

## 结果 / 验证记录

**PASS**（2026-09-16，V-E02、V-C06）。

`crates/pr-render/src/{table,width}.rs` 43 个测试覆盖每 field 横线、`╞═╪═╡` 表头底线、cell 内 JSON 2 空格缩进且多行 JSON 不产生额外分隔线、宽度按显示列数而非字节数、流式结果宽度冻结后不再回改（否则已经画出去的行会与后面的行不对齐）。主题与着色由 `crates/pr-render/src/theme.rs` 14 个测试守住。V-C04 另外证明了一件本 ADR 没写但必须成立的事：当终端对宽度的判断与我们不同时，`DrawMode::CursorReset` 的框线仍然对齐。
