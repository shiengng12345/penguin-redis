# ADR-038 · 每个功能至少一条纯文字入口；被终端或 IME 拦截的按键在该平台重映射，且重映射不得连带移除文字入口

- **状态**：accepted
- **日期**：2026-09-16
- **依据**：v2.1 §14.2、ASSIST-068
- **Phase 0 验证项**：V-C05、V-J04

## Context

F1–F6、Ctrl+R/P/N、Ctrl+Space 会被终端、窗口管理器或输入法拦截，组合多到无法穷举。把「这些键可用」当成前提，等于把功能的可达性交给我们控制不了的配置。

## Decision

验收标准是**「每个功能至少一条文字入口在所有组合下可用」**，不是「每个快捷键都能用」——后者不可能成立，写成目标只会让人去改测试。

§14.2 的八行做成数据而不是散落的常量，测试对这张表断言：

- 除「取消输入」外，每个功能都有文字入口。取消是唯一的例外，因为 Ctrl+C 是唯一一个每个终端都送达的键。
- 每条入口都能被 parse，且全是可直接键入的 ASCII（一条需要输入法才能打出来的「文字入口」，在输入法正是问题来源的场景里没有意义）。
- `Ctrl+Space` **不作任何默认键**——它在 macOS 上默认被输入法切换占用。
- 重映射**不能**连带移除文字入口。这一条单独测，因为重映射的实现方式很容易写成「把这个功能的入口表换掉」。

## Consequences

- 被拦截的键在该平台默认重映射并写进文档，而不是留给用户自己发现。
- 终端 × 输入法的矩阵属于人工记录（`MV-V-C05-*`）；它记录的是**差异**，不是通过条件——通过条件已经由文字入口承担。

## 结果 / 验证记录

**PASS**（2026-09-16，V-C05）。

裸 PTY 实测（macOS）：F1（SS3/CSI 两种编码）、F2（同）、F3、F4、F5、F6、Ctrl+R、Ctrl+P、Ctrl+N **全部送达**；`Ctrl+Space`（NUL）**未送达**——与 §14.2 的预判一致，也是它不作任何默认键的理由。

终端 × 输入法（含 macOS 上 F 键被系统占用的两种设置）→ `MV-V-C05-*` 人工记录，编号已分配，未执行；不阻塞，理由见上。
