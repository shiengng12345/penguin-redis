# ADR-010 · profile 的 secret reference 绑定 TLS 身份 + 服务身份（`TrustIdentity`），不绑定网络地址

- **状态**：accepted
- **日期**：2026-09-16
- **依据**：v2.1 §4.2、§4.3、§21.3、R07、R14、SEC-05
- **Phase 0 验证项**：V-D01、V-D02、V-D04

## Context

仅用 host:port 会把凭证发给已被替换的服务；仅用证书或 node ID 会在合法轮换/failover 时失效。

## Decision

`TrustIdentity = {endpoint, tls_identity, server_identity, auth_identity}`；凭证绑 `(tls_identity, server_identity)`；地址变化不重绑，身份变化重绑；Cluster 节点集在 `discovery_bounds` 内可变；轮换有过渡窗；直连形式不构造持久身份。跨资源提交（keychain + profile）用 journal + 启动 reconciliation。

## Consequences

审批令牌也绑完整 `TrustIdentity` 哈希（ADR-024）；导入 profile 的 endpoint 变更触发重审。

## 结果 / 验证记录

**PASS**（2026-09-16，V-D01、V-D02、V-D04）。

`crates/pr-security/tests/trust_binding.rs` 20 个测试证明凭证绑 `(tls_identity, server_identity)` 而不绑地址：地址变化不触发重绑，身份变化必定重绑，Cluster 节点集在 `discovery_bounds` 内可变而越界节点不经 `accept_confirmed` 根本无法记录。`credential_binding_hash()` **刻意不含 endpoint**，并有测试守住这个「缺失」——它看起来像疏漏，删掉它这条 ADR 就没了。跨资源提交用 journal + 启动 reconciliation，`crates/pr-profiles/src/journal.rs` 12 个测试覆盖写一半崩溃的各个切点。凭证存取在本机 Keychain 上实跑（`credentials.rs`，9 tests）。
