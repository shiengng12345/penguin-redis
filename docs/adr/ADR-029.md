# ADR-029 · 所有内存 / 并发 / 速率预算为单进程预算；无 daemon 架构不做跨进程仲裁

- **状态**：accepted
- **日期**：2026-09-16
- **依据**：v2.1 §12.5、§24.7、R08、R35
- **Phase 0 验证项**：V-F09、V-H01、V-A06

## Context

没有常驻进程就没有跨进程令牌桶；N 个 `prc` 对同一服务器的可见请求率最多 N 倍。假装有全局上限是误导。

## Decision

预算作用域 = 进程；`:complete status`/`:tasks` 显示本进程用量并注明多进程各自计费；服务器侧总量保护交给 ACL/`maxclients`/服务器限流。计量包含堆、result store、TUI layout、history page cache、spool 内存部分；不含只读 mmap catalog（单独报告）与 OS socket 缓冲。assistance 堆增量上限 12 MiB（子项 10 + 余量 2）。

## Consequences

附录 A `budget_scope = "per-process"`；V-F09/V-H01 实测。

## 结果 / 验证记录

**PASS**（2026-09-16，V-F09、V-H01、V-A06）。

预算作用域 = 进程，这一条在 V-F09 上以一种昂贵的方式被证明有必要：进程级的分配计数器在并行测试下**毫无意义**——一次测量报出 22.9 MiB，而被测集合只值 8.8，多出来的是同进程里另一个测试持有的 8 MB。修法是给称重单独一个二进制加一把互斥锁，空集检查改成结构性的。assistance 堆增量上限 12 MiB（10 + 2 余量）实测 8.53 MiB（`crates/prc/tests/budgets.rs` 的三个 `f09_*`，三平台跑）。计量口径按本 ADR：含堆、result store、TUI layout、history page cache、spool 内存部分；缓存的 `bytes()` 另外计入容器自身开销（`capacity() * size_of::<slot>()`），因为一个 2 MiB 的 field cache 实际占 5.2 MiB，宁可高估。
