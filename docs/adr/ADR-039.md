# ADR-039 · 用途搜索有两条到达命令的路：概念表与语料本身；两者按名次（RRF）融合，不按分数加权

- **状态**：accepted
- **日期**：2026-09-16
- **依据**：v2.1 §16.4、§13、R10、ADR-015、ADR-020、ADR-029
- **Phase 0 验证项**：V-F08、V-J04

## Context

§16.4 给用途搜索定了两个数：canonical 集 top-3 ≥ 95%，**独立 held-out 集 top-3 ≥ 80% / top-5 ≥ 90%**。
第一个只证明词表装下了它自己的内容；第二个是唯一说明「它能推广到没人预先写下的说法」的指标。

[ADR-034](ADR-034.md) 记录了为什么第二个数长期读不出来：四份语料同一个作者。那个问题解决之后
（由四位没看过词表的撰写人分别写出独立语料），真正的结论才露出来，而它不是「再加点词」：

| | 在它构建所依据的那份语料上 | 在一份**新的**独立语料上 |
|---|---:|---:|
| 一轮完整扩表（+164 词条、+6 implication、修正概念标注） | 67.3% → **86.5%** | 67.3% → **69.6%** |

**+19.2 个百分点里只有 2.3 个是泛化。** 手写同义词表覆盖的是写表人想到的说法；语言不按这个分布。
再写第五份、第六份语料只会把同一条曲线再画一遍。

## Decision

用途搜索有**两条**互相独立的到达命令的路：

1. **概念表**（原有）。词 → 概念 → 命令，带 implication、族过滤（`CONTAINERS`）、废弃降权。
   它知道字符串比较永远不知道的事：分数属于有序集合、删除一个 key 是 delete 而不是 remove。
2. **语料本身**（新增）。查询与**引擎已经见过的每一条表述**比对，按共享的实词与共享的汉字二元组打分。
   `scoring` 能找到 `score`，「按分数」能找到「分数」，**不需要任何人把它们写成同义词**。

两者**按名次融合**（reciprocal rank fusion，K = 12），**不按分数加权**。两个分数不在同一量纲上，
而一个「调到某份语料好看」的权重，正是 §16.4 的 held-out 规则要抓的那种调参。RRF 只用顺序。

**索引里放什么，是这条 ADR 的另一半**：canonical 集，加上**每一份已作废的 held-out 语料**。
它们都已经被用来扩过词表，是训练数据，留在架子上不会让任何东西变得更 held-out；五种语域的索引
显然比一种好。**不在索引里的只有一个目录**——`fixtures/assistance/find/heldout-independent/`，
并且有一条测试逐条断言它不在（`the_index_contains_nothing_from_the_live_independent_corpus`）。

## Consequences

- **语料进了二进制。** 2,285 条表述随 `pr-intelligence` 一起编译（`src/phrases.rs`，由 fixtures 生成，
  有测试比对防漂移）。这与 ADR-020 的「默认零联网」一致：泛化能力来自本地数据，不来自一次请求。
- **预算**：gram 存成 32 位哈希而不是 `String`，索引倒排；recall 测试从 0.9 s 涨到 14.9 s 再回到
  **1.2 s**。一次 32 位碰撞只会轻微扰动一个分数，换回来的是几兆内存，这个交换是明写的。

  **第一次报出来的增量（8672 KiB）是假的，这里把它改正。** `prc` 目前没有任何代码路径调用
  `Finder::new()`——Phase 0 的 REPL 还没接上用途搜索——于是链接器把整张表丢掉了，
  `--probe assistance-on` 量到的「assistance 堆」里根本没有它。`strings target/release/prc` 里
  一条语料都找不到，二进制大小也一个字节没变，这才露的馅。把 `Finder::new()` 放进探针之后
  （它本来就该在：探针定义了什么算 assistance），真实数字是 **9296 KiB**（预算 12288 KiB，
  ADR-029），也就是整套用途搜索约 **720 KiB**，余量 2992 KiB。
  `f09_the_assistance_probe_really_holds_a_saturated_working_set` 现在顺带断言探针报出的
  `find_commands` ≥ 190，好让同一类「量了个空气」不会再发生一次。
- **`Hit::matched` 对纯词法命中的那一部分是空的**。UI 需要「为什么是它」时，概念那一路仍然给得出
  理由；词法那一路给不出，这是它的代价，不假装有。
- **概念表没有因此变得不重要**：它仍然是唯一知道族与蕴含的那一层，也是唯一在查询用了一个语料里
  从未出现过的词时还能答话的那一层。两条路都留着，是因为它们错的地方不一样。

## 结果 / 验证记录

**PASS**（2026-09-16，V-F08）。

§16.4 的门槛在一份由四位从未见过词表的撰写人写的语料上达成：

| 指标 | 门槛 | 实测 |
|---|---:|---:|
| 独立 held-out top-3 | ≥ 80% | **83.2%**（331 / 398） |
| 独立 held-out top-5 | ≥ 90% | **90.5%**（360 / 398） |
| canonical top-3 | ≥ 95% | **99.4%**（713 / 717） |

机制改动是**在没有读过那份语料的 miss 的前提下**做出来的——设计依据来自上一轮已作废语料的证据，
所以那份语料仍然是一次 held-out 测量，只读过它的总数。

`the_index_contains_nothing_from_the_live_independent_corpus` 上线当天就抓到三条：live 语料与一份
已作废语料逐字撞了三句。它们的原作者改写了那三句（同样没有看任何东西）。撞车之前 83.7 / 91.0，
之后 83.2 / 90.5——那 0.5 个百分点是三道「答案已经在索引里」的题。

证据：`crates/pr-intelligence/src/{find,phrases}.rs`、`crates/pr-intelligence/tests/find_recall.rs`
（17 tests）、`fixtures/assistance/find/{canonical,heldout-independent,heldout-independent-v1-void}/`。
