# ADR-017 · 动态候选按 `ObservationScope`（profile/service identity/DB/auth epoch/policy epoch/topology epoch）隔离；buffer revision 防迟到污染

- **状态**：accepted
- **日期**：2026-09-16
- **依据**：v2.1 §12.6、§12.8、R13、附录 A
- **Phase 0 验证项**：V-F05、V-F06

## Context

dev 的 key 名不能出现在 prod 的候选里；异步结果不能覆盖用户正在按 Enter 的行。

## Decision

缓存键为完整 scope 而非 host:port；AUTH/HELLO/SELECT/RESET/重连/拓扑变化触发失效；每次输入递增 revision，worker 结果回 UI 时全部标签比对不符即丢弃；`CandidateId` 稳定；粘贴期间暂停逐字分析。

## Consequences

附录 A `scope` 字符串含 topology-epoch；ASSIST-026~033、088。

## 结果 / 验证记录

**PASS**（2026-09-16，V-F05、V-F06）。

`crates/pr-intelligence/src/scope.rs` 14 个测试证明缓存键是完整 `ObservationScope` 而不是 `host:port`——两个指向同一地址但 DB 或 auth epoch 不同的会话，共享候选就是把一个库的 key 名提示给另一个库。AUTH / HELLO / SELECT / RESET / 重连 / 拓扑变化各有失效用例。`crates/pr-intelligence/src/broker.rs` 11 个测试覆盖 revision：worker 结果回到 UI 时全部标签比对，不符即丢弃；粘贴期间暂停逐字分析（这一条与 V-C03 的 paste staging 是同一件事的两端）。
