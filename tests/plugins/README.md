# L2 插件外部进程隔离（V-D09，v2.1 §30.4、R45）

宿主在 `crates/pr-render/src/plugin.rs`，矩阵在 `crates/pr-render/tests/plugin_isolation.rs`（17 tests），故意失灵的插件在 `xtask/plugin-fixtures/`。

## 为什么必须是外部进程

§30.4 推翻了 v2.0 的说法，并给了理由：

> 不存在「进程内加载原生动态库」的级别：**Rust 的 panic/abort/OOM 无法在同进程内可靠隔离**，v2.0 的这一表述不再成立。

所以隔离能力就是 OS 的进程边界，宿主的职责因此窄而可验：拉起、喂输入、最多收 N 字节、T 之后杀掉，并且**绝不让插件做的任何事变成宿主做的事**。

一个会正常工作的插件证明不了隔离。所以 fixture 是按「真实插件迟早会怎样坏」和「恶意插件会怎样选」写的。

## 每一次失败都断言同样两件事

1. 宿主还活着、还能渲染（进程边界守住了）
2. **用户已经拿到的结果没有变**——渲染偏好绝不能弄丢用户已有的数据

## 矩阵

| fixture | 干了什么 | 期望 | 实际 |
|---|---|---|---|
| `ok` | 正常渲染 | 成功，且输入真的到达了插件 | ✅ 对照组 |
| `panic` | 平常代码坏掉的方式 | `Crashed`，宿主存活 | ✅ |
| `abort` | 跳过 unwind，SIGABRT | `Crashed(killed by signal 6 (SIGABRT))` | ✅ |
| `hang` | 什么都不产出的死循环 | 到点被杀，不是等 | ✅ 300 ms 预算内返回 |
| `flood` | 每次 64 KiB，无限产出 | 截断并杀掉，**宿主不跟着长** | ✅ RSS 增长 < 64 MiB |
| `oom` | 分配并触碰内存直到耗尽 | 死的是插件 | ✅ |
| `wrong-shape` / `garbage` | 合法 JSON 但形状不对 / 根本不是 JSON | `Malformed`，理由具名 | ✅ |
| `output-then-fail` | 输出完好，然后非零退出 | 不采信输出 | ✅ |
| `escapes-json` | 正确编码的终端转义 | 经 SafeText 中和 | ✅ |
| `escapes-raw` | JSON 字符串里塞裸控制字节 | `Malformed`，**不修复** | ✅ |
| `echo-env` | 报告自己拿到的环境变量 | 只有 `PENGUIN_PLUGIN_API` | ✅ |
| `slow` | 300 ms 后正常返回 | 不算 hang；但 50 ms 预算下会超时 | ✅ |
| 未授权的名字 | — | **根本不拉起** | ✅ |

## 几个刻意的设计选择

**截断是失败，不是「短一点的成功」。** 半张渲染不是渲染，显示它就是 §24.4 禁止的静默截断。

**环境是构建出来的，不是继承来的。** 先继承再删掉已知的坏名字，是错误的默认：它对每一个没人想到的变量都 fail open，而凭证路径恰恰就是没人想到的那一类。所以断言的是子进程的环境**很小**，不是某个名字不在——canary 用 `CARGO_MANIFEST_DIR` 和 `PATH`，并先断言父进程确实有它们，否则这条测试会因为什么都没检查而通过。

**被渲染的数据永远不会变成 argv。** 一个会变成参数的值，是一个在等合适取值的注入。授权项固定参数，数据走 stdin，在那里它只是字节。

**默认 deny 必须意味着「不运行」，不是「运行了但忽略结果」。** 测试的做法是：授权一个会崩溃的插件，然后去要一个**没被授权**的名字——一个见到什么就拉起什么的宿主，会在这里把崩溃的那个跑起来。

**输入在独立线程里写。** 内联写会和「产出先把输出管道写满、之后才读输入」的插件死锁——`flood` 干的正是这件事。

**无条件 kill 然后 wait。** 对已退出的子进程 `kill` 无害；漏掉 `wait` 则每次调用留一个僵尸，而渲染器是会被频繁调用的。症状会在很久以后以「fork 不了」的形式出现，所以有一条跑 50 次崩溃再确认还能拉起的测试。

**exit status 要说人话。** `exit status: 134` 对操作者毫无信息；`killed by signal 6 (SIGABRT)` 告诉他插件是 abort 了——这和「插件返回了错误」是两场不同的对话。

## 写测试时发现的一件事

`escapes-raw`：插件在 JSON 字符串里写裸 ESC，产出的**不是合法 JSON**。宿主必须拒绝而不是修复——修复意味着开出一条 JSON 层从未检查过的、通往终端的通路。这一条被单独立为一个 case，与「合法 JSON、内容恶意」的 `escapes-json` 分开：后者才是 §23.6 真正说的那件事，前者由解析器挡住。

## 还没做的

- **L1 声明式插件**（TOML/JSON 的 renderer 映射、decoder 组合、主题）：不需要验证隔离（进程内解释执行、无任意代码），归 Phase 7。
- **复用受限池**：§30.4 允许「每次调用重新拉起**或**复用受限池」。当前实现是前者；池化要等有真实插件、能测出重新拉起的代价时再说。
- **显式声明并批准的文件/网络路径**：目前一律没有。
